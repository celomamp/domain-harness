Domain Harness — UX Design Validation Report

_bmad-output/planning-artifacts/ux-designs/ux-domain harness-2026-10-09/

The pair is a behavioral contract a story can implement, and it is not a visual contract. Every user journey and every functional requirement is named under Key Flows, component behavior is specific, and the experience sections are in the required order. Color, type, radius, spacing, and component visuals are empty on purpose, and the rubric treats missing hex as critical, so implementation must not mirror a palette from this draft. A few load-bearing paths still force a consumer to invent the step that reaches the climax, the Read API flow, or which publish order is in force.

The accessibility review shifts that picture. A builder cannot meet WCAG 2.2 AA from these spines: contrast has no pairs to measure, and below 768px publish and accept are withheld. Keyboard operation of those actions, several error texts, and a missed Accepted-deviation alert are unspecified, so the AA assumption is not yet a contract a builder can implement.

Accessibility review

thin review-accessibility.md

Thin. The floor gives text labels, reading-order tab, Esc, announced denials and plan-refusals, text beside the adherence series, status words as words, and a Correction instruction on each Deviation. A builder still cannot meet WCAG 2.2 AA: contrast cannot be verified while tokens are unset, and below 768px the spine withholds publish and accept.

critical

Contrast targets cannot be verified

DESIGN.md Colors; EXPERIENCE.md Accessibility Floor
WCAG 1.4.3 and 1.4.11 have no pairs to measure, including status words, the focus indicator, and adherence-series marks. The floor assumes AA and then places contrast in an empty DESIGN.md.
Fix: Before AA can be claimed, name foreground and background pairs and state the AA ratios (4.5:1 text, 3:1 large text and non-text). Leave the brand values unset until that decision.
critical

Publish and accept are withheld below 768px

EXPERIENCE.md Responsive and Platform
WCAG 1.4.10 requires the same functionality at 320 CSS pixels. 200% and 400% zoom land below 768px. A person who cannot use a wide viewport cannot publish a Standard or accept a Deviation.
Fix: Keep publish, accept, filter, and sign-in available at 320 CSS pixels, stacked, with vertical scroll. Allow two-dimensional scroll only for evidence tables and the adherence plot. Remove the wider-window gate.
high

Pointer-first leaves the primary actions without a keyboard path

EXPERIENCE.md Interaction Primitives
Tab order and Esc are specified. Nothing requires a key to activate a row, change the filter, publish, accept, or sign in. Focus is not moved into a form, returned on Esc, or kept visible, and a trap is not forbidden.
Fix: Give every pointer action a keyboard equivalent. Move focus to the first field when a form opens, return it on Esc, never trap it, and require a visible focus indicator whose contrast stays in DESIGN.md.
high

Four failures are not identified in text

EXPERIENCE.md State Patterns
A cycle, a description with no Project, a compilation-drop, and unbound Application lack a text identification and a recovery. compilation-drop is not announced. Sign-in errors cannot be checked while authentication is open.
Fix: Name the object, state what happened in glossary terms, and state the recovery in one sentence. Announce compilation-drop the same way as a denial.
high

A missed Accepted-deviation alert is not perceivable

EXPERIENCE.md acceptance-form
The alert is on the panel and names the Application, the Standard, and the end date. Nothing says it remains until the Buyer perceives it, or that the end date stays visible for the life of the record.
Fix: Show the end date and the alert interval as text for as long as the Accepted deviation is stored. Keep the alert until the Buyer dismisses it or the end date passes.
high

Host strings omit failures that are not a Deviation

EXPERIENCE.md CLI Gate, CI Gate, Agent Guidance
unbound Application, a missing Project identification file, and a duplicate Application id can fail the host without a required sentence. A passing CLI run can print nothing.
Fix: Require a text sentence for those failures and for a run that did not complete. Keep the Correction instruction on every Deviation. Keep miss as the word miss, with the asked-for subject.
medium

Target size is unspecified

DESIGN.md Layout and Spacing
WCAG 2.5.8 requires 24 by 24 CSS pixels or the spacing exception. Spacing tokens are empty.
Fix: State that minimum for every pointer target. Do not set a spacing scale in this review.
medium

Page language is not required in the accessibility tree

EXPERIENCE.md Voice and Tone
Microcopy is assumed English. The floor never requires the page language to be programmatic. Company-authored fields have no language rule.
Fix: Require the panel's programmatic language to be English. When an authored field is in another language, identify that part.
medium

Motion can flash or run without a pause

EXPERIENCE.md Accessibility Floor
Nothing forbids flashing more than three times in one second, or requires pause, stop, or hide when the series or the alert moves for more than five seconds.
Fix: Forbid that flashing. If the series or the alert moves, blinks, or updates for more than five seconds, give the Buyer a way to pause, stop, or hide it.
medium

Name, role, and value stop short of the plot, the tree, and the drop

EXPERIENCE.md Accessibility Floor
The plot has no text alternative as one graphic. project-node does not require tree semantics. Row accessible names and evidence-table headers are unset. compilation-drop can be a mark with no name.
Fix: Name the announcement role for denial and plan-refusal. Require a text alternative for the plot, tree semantics for project-node, an accessible name on each activating row, and header cells on evidence tables.
