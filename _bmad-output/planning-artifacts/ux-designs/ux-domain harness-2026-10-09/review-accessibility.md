# Accessibility Review — domain harness

## Overall verdict

Thin. The accessibility floor gives a builder text labels on every control, reading-order tab, Esc to leave a form, announced denials and plan-refusals, text beside the adherence series, status words as words, and a Correction instruction in the text of each Deviation on the CLI and CI logs. A builder still cannot meet WCAG 2.2 AA for the management panel from this pair: contrast cannot be verified while tokens are unset, and below 768px the spine withholds publish and accept. Keyboard operation of those actions, several error texts, and a missed Accepted-deviation alert are unspecified, so the AA assumption is not yet a contract a builder can implement.

## Findings

- **critical** Contrast targets cannot be verified (DESIGN.md Colors, Typography, Components, Do's and Don'ts; EXPERIENCE.md Accessibility Floor). Color, type, radius, elevation, and spacing tokens are empty, component visual specs are unset, and the draft forbids inventing token values until DESIGN.md leaves draft. WCAG 1.4.3 (text contrast) and 1.4.11 (non-text contrast) have no pairs to measure, including for pass/fail, open/accepted, approved/prohibited/required, the focus indicator, and adherence-series marks. The floor places contrast in DESIGN.md and then assumes WCAG 2.2 AA. A builder who follows both files cannot implement the ratios and cannot claim AA. *Fix:* Before AA can be claimed, DESIGN.md must name a foreground and background for each text role and state that each pair meets the AA text ratio (at least 4.5:1, or 3:1 where the type ramp defines large text); name pairs for the status words and state that the word carries the state; name non-text pairs for control boundaries, the focus indicator, and adherence-series marks and state that each meets the AA non-text ratio (at least 3:1 against adjacent colors); and state a type ramp that still works at 200% zoom and a spacing rule that survives text-spacing overrides. Leave the brand values unset until that decision. Do not fill the ratios in implementation while this file is draft.

- **critical** Publish and accept are withheld below 768px (EXPERIENCE.md Responsive & Platform). The panel is assumed to be a responsive web application. At 768–1279px, tables stack under the project-filter. Below 768px, the panel stays readable, and publish and accept ask for a wider window. WCAG 1.4.10 Reflow (AA) requires the same information and functionality at a width of 320 CSS pixels, with vertical scrolling; two-dimensional scrolling is limited to parts that need it, such as a table or a plot. 400% zoom on a 1280px display is a 320px CSS viewport, and 200% zoom (1.4.4) on that display is 640px, so both land below 768px. A person who cannot use a wide viewport cannot publish a Standard or accept a Deviation. "Desktop-primary" and "not a second mobile product" do not waive 1.4.10. *Fix:* Keep publish, accept, filter, and sign-in available at 320 CSS pixels wide, stacked, with vertical scroll. Allow two-dimensional scroll only for evidence tables and the adherence plot. Remove the wider-window gate.

- **high** Pointer-first leaves publish, accept, filter, and sign-in without a keyboard path (EXPERIENCE.md Interaction Primitives, Accessibility Floor, Key Flows UJ-2, UJ-4, FR-2, FR-15, FR-29). People point at a row or a form. The keyboard contract is tab order in reading order, and Esc leaves a form without publishing, accepting a Deviation, or creating a Project. Nothing requires a key to activate application-row or cross-check-row, to change project-filter, to publish standard-form, to submit acceptance-form, or to complete sign-in. Nothing moves focus into an opened form, returns focus on Esc, forbids a keyboard trap, or requires a visible focus indicator (2.4.7, 2.4.11). A click-only handler on those actions satisfies the written sentences and fails 2.1.1 Keyboard for the Buyer, the Standard owner, and the Builder. *Fix:* Give every pointer action on those controls a keyboard equivalent. Keep tab order in reading order. Move focus to the first field when a form opens, and return focus to the opener on Esc. State that focus is never trapped. Require a visible focus indicator; its contrast stays in DESIGN.md.

- **high** Four failures are not identified in text, and recovery is unspecified (EXPERIENCE.md State Patterns, Component Patterns denial, compilation-drop, project-node, boilerplate-result; Key Flows UJ-2, UJ-4, FR-5, FR-26). A cycle is rejected with no message, no identification of the parent that closes the cycle, and no recovery. A description with no Project is not created, with no error text and no instruction to choose a Project (3.3.1, 3.3.3). compilation-drop is visible to the Buyer and shows no partial payload; it is not announced, unlike denial and plan-refusal, and it does not say in text that the schema failed or what the Buyer can do next. The Application surface shows unbound Application as a failure and does not say how to recover (restore the Project identification file, or resolve an id already bound to another repository). A Builder who accepts their own Deviation does get an announced denial; that denial still does not say that the Buyer records the acceptance. Sign-in errors cannot be specified while the authentication mechanism is an open gap, so 3.3.1 and 3.3.8 (accessible authentication) cannot be checked on the way into the panel. The miss path on Gaps is in better shape: gap-row shows the Application, the tool, the subject, and a count. *Fix:* For each of these failures, name the field or object in text, state what happened in the glossary terms already used (cycle rejected, description with no Project, compilation-drop, unbound Application, denial), and state the recovery in one sentence. Announce compilation-drop the same way denial and plan-refusal are announced. When sign-in is specified, require an error in text and a method that does not depend on a cognitive function test.

- **high** A missed Accepted-deviation alert is not perceivable (EXPERIENCE.md acceptance-form, State Patterns Accepted deviation, Information Architecture, UJ-4, Open gaps). The Buyer sets a start, an end, and an alert interval. The alert names the Application, the Standard, and the end date, and it is shown on the management panel. No email is assumed. Nothing says the alert remains until the Buyer perceives it, or that the end date and the interval stay visible on the Accepted deviation for its whole life. After the end, that match key fails the Gate again. A Buyer who is away when the interval fires can lose the only warning. The end date is user-chosen, so this is a missed status (4.1.3), not a session timeout. *Fix:* Show the end date and the alert interval as text on the Accepted deviation for as long as it is stored. Keep the alert on the panel until the Buyer dismisses it or the end date passes. Name the Application, the Standard, and the end date in that persistent text.

- **high** Host strings omit the failures that are not a Deviation (EXPERIENCE.md State Patterns CLI Gate, CI Gate, Agent Guidance; correction-instruction; plan-refusal; Accessibility Floor). Text-only hosts still have to put the outcome in the string. Color, an exit code, or an empty payload cannot be the only signal. What is already specified: each Deviation includes its Standard id and a Correction instruction; an empty authored instruction is filled with one sentence from the status, the conflict slot, and the approved entry in that slot when one exists; the CI log includes one Correction instruction naming the Standard and a compliant alternative; Agent Guidance returns the Standard or a miss as text, and a miss must not invent a Standard. What is missing: unbound Application and a missing Project identification file fail the CLI and the CI step without a required printed sentence or a Correction instruction. Guidance refuses another Project's Standards when the file is missing or unreadable, and refuses a second repository that presents an already bound Application id, without a required sentence. plan-refusal is omitted from the pipeline log and the MCP response, including when the CI Gate is used off the Team plan, so those hosts can fail with no words. A passing run is exit zero and can print nothing; the words pass and fail are required on the panel schema and not in the CLI print. *Fix:* Require a text sentence on the CLI print, the CI log, and the MCP response for unbound Application, a missing or unreadable Project identification file, a duplicate Application id, and a run that did not complete. Keep the Correction instruction on every Deviation. Keep the miss as the word miss, and include the asked-for subject in that sentence. If the plan name stays off the pipeline and the MCP response, still print a text reason the step or the tool did not run.

- **medium** Target size is unspecified (DESIGN.md Layout & Spacing, Components; EXPERIENCE.md Component Patterns). WCAG 2.5.8 Target Size (Minimum) is 24 by 24 CSS pixels, or the spacing exception in that criterion. Spacing tokens are empty, and the draft forbids inventing them. Row activators (application-row, cross-check-row), project-filter, publish, accept, and sign-in have no minimum. A dense evidence table can ship under the minimum and still match both spines. *Fix:* In DESIGN.md spacing, state a minimum target of at least 24 CSS pixels, or the WCAG 2.2 spacing exception, for every pointer target, including activating rows and form controls. Do not set a spacing scale in this review.

- **medium** Page language is an English assumption, and authored fields have no language (EXPERIENCE.md Voice and Tone, Accessibility Floor). Panel microcopy is assumed English. The PRD sets no locale. WCAG 3.1.1 requires the page language to be programmatically determined; the floor never requires that. Glossary terms (Standard, Gate, Adherence, Deviation, miss, unbound Application, and the rest of that list) are English product words used as written; they are not a second language and do not need their own language mark. Usage rules, Correction instructions, and Project level names are authored by the Company, and their language is unset. If those strings are in another language than the panel, WCAG 3.1.2 requires that part to be identified. *Fix:* Require the management panel's programmatic language to be English, matching the microcopy assumption. When a Standard, a usage rule, a Correction instruction, or a level name is in another language, identify that part. Keep glossary terms exactly as written.

- **medium** Motion is unset, so the flash and pause rules are open (DESIGN.md has no motion tokens; EXPERIENCE.md Accessibility Floor, adherence-series, acceptance-form). WCAG 2.2 AA includes 2.3.1 Three Flashes or Below Threshold (Level A): content must not flash more than three times in any one second. It does not include 2.3.3 Animation from Interactions, which is AAA, so a general motion preference is outside this pass. Nothing in the spine forbids flashing. The adherence series and the recurring Accepted-deviation alert can move, blink, or auto-update, and WCAG 2.2.2 Pause, Stop, Hide (Level A) is also inside AA. A builder can add a flashing alert or an endless series and still match the spine. *Fix:* Forbid flashing more than three times in any one second. If the series or the alert moves, blinks, or updates for more than five seconds, give the Buyer a way to pause, stop, or hide it. Do not specify an animation style.

- **medium** Name, role, and value stop short of the plot, the tree, and the drop (EXPERIENCE.md Accessibility Floor, adherence-series, project-node, compilation-drop, application-row, cross-check-row). Denial and plan-refusal are announced and are not conveyed by appearance alone; the role of that announcement (status or alert) is unnamed. adherence-series is not color-only: the Adherence value and the Deviation count are text, which covers 1.4.1 for the marks. The plot itself has no role and no text alternative as one graphic. Status words are already words: pass or fail, open or accepted, approved, prohibited, or required. project-node stores a parent and a level name and does not require tree semantics (parent, child, level) in the accessibility tree. application-row and cross-check-row are covered by "every control has a text label," and the string that forms the accessible name is unset. Evidence tables have no header-cell requirement. compilation-drop is specified only as visible, so a mark with no name can be the whole drop. *Fix:* Name the announcement role for denial and plan-refusal. Require the series numbers as text and a text alternative for the plot. Expose project-node as a tree with the Project name and the level name. Set the accessible name of an activating row from the Application and, for a cross-check, the check type. Require header cells on evidence tables. Announce compilation-drop in text, as in the error finding above.
