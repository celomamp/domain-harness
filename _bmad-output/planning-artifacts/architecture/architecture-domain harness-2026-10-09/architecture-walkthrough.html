Domain HarnessArchitecture walkthrough

Four surfaces. One answer.

Guidance, the CLI Gate, the CI Gate and the Read API must never disagree about which Standard applies. The architecture exists to make that true by construction, not by discipline.

Paradigm

Hexagonal. One pure resolver core, thin adapters around it.

Unit of truth

An immutable, signed, hash-addressed Standard bundle.

Trust boundary

Company data stays in the Company environment. Only a closed catalog of Compilations leaves.

21 architecture decisions (AD-1 to AD-21) bind this. This deck walks the ones a new team member must know first. The full contract is ARCHITECTURE-SPINE.md.

One resolver, many adapters

Resolution logic exists in exactly one package. Everything else is I/O around it.

Extra rule: packages/extractor turns files into revision facts, once, with a versioned schema (AD-18). Two Gates cannot parse lockfiles differently.

Two environments, one direction of travel

Standards flow in as signed bundles. Compilations flow out. The Company environment never accepts an inbound call from the vendor.

What never leaves: source code, prompts, Gate logs, Guidance records. What the vendor holds for the pilot: Standard content (AD-3, a PRD amendment).

The bundle is the contract

Anything the Gate or Guidance may know arrives inside it. No side channel.

contains

Standard versions, Modules, owners, the Project tree, Locked rules, the Application list (id → Project) and Accepted deviations.

proves

Signed with a key id in the verifier's trust set, tenant id inside the payload, per-tenant monotonic sequence. An older bundle is refused.

why the Project is not in the repo file

A Builder can edit a file. The Project is derived from the bundle by Application id, so a Builder cannot shed a Locked rule.

activation

One atomic active pointer in the record store. Every call pins the bundle hash at start and records it.

The Gate is a pure function

Same inputs, same Deviations. The clock is an input, never read ambiently.

One door out

A single Collector module owns the only record-to-Compilation projection. No adapter has a path to the vendor.

Subjects cross only as slot-name tokens. Free text becomes a tenant-keyed hash. The catalog is closed: Guidance, Gate run, Deviation, Binding refusal, Bundle status, Collector health (AD-20).

What you decided, and what waits

decided

Hexagonal core. Company-run service. Vendor-held registry for the pilot. Build, don't adopt. TypeScript monorepo. Signed bundles. Shared Postgres with tenant scope and RLS. Fail closed on stale. Network trust plus fingerprint.

deferred

Company-keyed encrypted Standards. Per-Application tokens and SSO. Cloud provider, SLOs, DR. Decision agent. Impact analysis and batch acceptance. Signing key custody.

assumption MCP SDK v2 status conflicted across sources on 2026-10-09. v1.x is pinned. Confirm the npm latest tag at scaffold. TypeScript 7 tooling compatibility also needs a scaffold check.
